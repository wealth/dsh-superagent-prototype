---
name: dsh-superagent-agentmail
description: Читать переписку в почтовом ящике AgentMail, на которую опирается тикет.
---

Исполнители используют `orchestrator_read` для контекста письма по мере необходимости: `trigger/<id триггера>` — текст письма, куда он пошёл, письмо, на которое он отвечает, и соседние письма его треда. Письмо имеет вид `{ id, from, at, text, reply_to? }`: `id` — id письма AgentMail, `from` — адрес отправителя, а `reply_to` — id письма, на которое данное отвечает. Если в ответе есть `next_resource`, за ним есть ещё письма: передайте его в `orchestrator_read` дальше. Чтение ничего не создаёт и не отправляет.

Ответы публикуются в тред письма через сам источник, отдельных инструментов для этого не нужно: источник отвечает от имени ящика `DSH_SUPERAGENT_AGENTMAIL_INBOX`, и ответы приходят в тот же тред. Новые письма в подписанном треде приходят исполнителю без дополнительных действий.

Не используйте SMTP, IMAP или прямые запросы к API AgentMail, если их нет в инструкциях окружения: ключ API принадлежит источнику и не передаётся исполнителю. Адрес отправителя исходного письма берите из переменной `DSH_SUPERAGENT_AGENTMAIL_FROM`, адрес ящика — из `DSH_SUPERAGENT_AGENTMAIL_INBOX`.

Перед существенной работой над новым запросом человека вызовите `orchestrator_ack` с исходным id триггера и коротким текстом, относящимся к запросу. Подтверждение уходит один раз ответом в тред письма. Автоматические рассылки и уведомления не подтверждайте.
