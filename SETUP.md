# НАСТРОЙКА

Инструкции для агента, который настраивает dsh-superagent вместе со своим оператором. Если вы человек, попросите вашего агента-разработчика прочитать этот файл и следовать ему.

## Как выполнять настройку

Настройка следует [docs/000-philosophy.md](docs/000-philosophy.md): она забирает как можно меньше внимания оператора.

- **Перед первым вопросом** прочитайте только этот файл и `docs/000-philosophy.md`, и один раз выполните приведённую ниже проверку. Не читайте ничего другого, пока не будут собраны все ответы.
- **Задавайте один вопрос в одном сообщении,** об одном предмете. Ждите ответа, прежде чем задать следующий. Пропускайте вопрос, на который уже отвечает проверка.
- **Держите каждое сообщение в пределах 300 слов,** если оператор не попросит больше. К каждому вопросу давайте рекомендуемый ответ, который оператор может принять одним словом, и одно предложение о том, почему это важно.
- **Не выполняйте ничего, пока задаёте вопросы.** Соберите все ответы, затем отправьте одно сообщение с полным планом и выполняйте его только после подтверждения оператора.
- **Никогда не запрашивайте секрет в чате.** Шаги, требующие действий оператора — например, создание аккаунта, вход в CLI или ввод секрета приложения — объедините в одно сообщение с точными командами для запуска в его собственном терминале.
- **Обучайте философии через вопросы,** по одному предложению за раз, а не в виде лекции.

## 1. Проверка

Выполните из этого checkout один раз, а результат держите при себе:

```sh
node -v; pnpm -v; git --version; tmux -V; python3 --version; gh --version | head -1; dsh --version
gh api user --jq .login
command -v lark-cli
grep -l -E 'id: dsh-superagent\b' "${DSH_HOME:-$HOME/.dsh}"/profiles/*/cordis.patch.yml 2>/dev/null
```

- **Предварительные требования:** Node.js 22.19+ или 24+, pnpm, git 2.32+, tmux, Python 3.8+, GitHub CLI 2.48+ и DSH в пределах диапазона `engines.dsh` из `package.json`. Недостающий компонент становится пунктом плана, а не вопросом. DSH также нужен поставщик модели; если оператор никогда не запускал DSH с моделью, её настройка — шаг оператора.
- **Логин оператора:** результат `gh api user` — собственный логин оператора на GitHub, используется как рекомендация в вопросе 5.
- **Существующий профиль:** профиль с записью `dsh-superagent` — это более ранняя настройка: спросите, продолжать ли её, сохраните его конфигурацию и прочитайте Upgrade в `docs/006-deployment.md`.

## 2. Вопросы

Задавайте в этом порядке, по одному в сообщении, следуя потоку работы в [docs/001-domain.md](docs/001-domain.md): сначала откуда берутся Триггеры, затем кто может запрашивать работу там, затем что делает Исполнитель с Тикетом. Рекомендации указаны в скобках.

**Источники: откуда берутся запросы.**

1. **Источники.** Должен ли агент принимать запросы только с GitHub или также из чатов Feishu? [Только GitHub, если команда не работает в Feishu.]
2. **Репозиторий.** Над каким репозиторием github.com должен работать агент, в виде `owner/name`?
3. **Аккаунт агента.** От имени какого аккаунта GitHub будет действовать агент? [Выделенный аккаунт, никогда собственный аккаунт оператора: всё, что пишет агент, публикуется под этим именем.] Он может ещё не существовать; его создание — шаг оператора.
4. С Feishu: **какие чаты,** по имени? Агент определит их id после настройки бота.

**Политика: кто может запрашивать работу.**

5. **На GitHub.** Какие логины GitHub могут запрашивать у агента работу? [Только `<логин оператора>`: агент действует только для людей из этого списка, а короткий список снижает шум команды, пока оператор изучает, как ведёт себя агент.]
6. С Feishu: **кто может запрашивать в Feishu?** [Все в первом чате, в синхронизации с его участниками.]

**Исполнение: что агент делает с Тикетом.**

7. **Checkout.** Из какого локального клона репозитория должен делать checkout каждый Тикет? [Новый клон в `~/src/<name>`.]
8. **Идентичность коммитов.** Кого агент должен указывать автором своих коммитов? [Аккаунт агента, чтобы его работа была наглядно его собственной.] Другая идентичность, например оператора, помещается в секцию промпта Delivery requirements.
9. **Auto-merge.** Должен ли агент включать auto-merge на своих pull request, когда они готовы и одобрены? [Нет: люди мерджат, пока pull request агента не будут стабильно корректны.] Агент никогда не включает его от имени аккаунта агента, поэтому при ответе «да» нужен GitHub CLI другого аккаунта, который может мерджить: попросите оператора войти в него среди шагов оператора и укажите его в Delivery requirements. При ответе «нет» удалите абзац про auto-merge из Delivery requirements.

Не спрашивайте о значениях, у которых есть удачное значение по умолчанию; вместо этого перечислите их в плане:

- профиль `superagent`, копия Web-профиля DSH, отделённая от профиля, в котором работает оператор, чтобы он перезапускался, не закрывая его Сессии; порт `3082`; директория состояния `<home>/.dsh/state/superagent` как абсолютный путь;
- ежечасная проверка из собственного профиля оператора, которая чинит dsh-superagent, когда он не запущен;
- префикс ветки `agent/`;
- режим приёма `observe`, который фиксирует проактивную работу, не выполняя её, а также правила и секции промпта по умолчанию;
- с Feishu: бот читает только упоминания, а прямые сообщения включены.

## 3. План

Отправьте одно сообщение, в пределах 300 слов: что будет установлено, аккаунты и CLI, настройки для сохранения, шаги оператора и значения по умолчанию. Запросите одно подтверждение.

## 4. Выполнение

1. **Сначала шаги оператора.** Прочитайте раздел Accounts в `docs/006-deployment.md`, сами напишите обёртки CLI, затем отправьте одно сообщение с тем, что может сделать только оператор: создать аккаунт агента и, при auto-merge, войти в CLI от имени аккаунта, который его включает, принять приглашение в репозиторий от имени аккаунта агента, выполнить `auth login` для каждой обёртки, а для Feishu создать и опубликовать приложение-бота и выполнить команду `config init` с его секретом. Дождитесь, пока оператор подтвердит завершение, затем проверьте каждый логин командой `<wrapper> api user --jq .login`.
2. **Установка и запуск.** Следуйте разделам Install, Machine configuration и Start and stop в `docs/006-deployment.md`. Пропустите `git clone` этого репозитория: вы находитесь в его checkout. Клонируйте репозиторий вопроса 2, если вопрос 7 предполагал новый клон. При существующем профиле пропустите команду `dsh superagent --from-default-profile`, которая заменила бы профиль и удалила его `cordis.patch.yml`, и редактируйте этот файл вместо его замены.
3. **Настройки.** Сохраните их через Management API из `docs/006-deployment.md` в таком порядке: Источник `github`, Источник `feishu`, если используется, блок `policy` со списками разрешённых (для Feishu сначала определите id чатов при помощи CLI бота) и блок `executor` с командой prepare из ответа на вопрос 7. Затем сохраните промпты с идентичностью коммитов из вопроса 8 и ответом про auto-merge из вопроса 9 в Delivery requirements. Сохранение, возвращающее `restarting: true`, перезапускает dsh-superagent: дождитесь, пока `scripts/dsh-superagent status` перестанет завершаться с кодом 1, прежде чем отправлять следующий запрос, и заново прочитайте ревизии из `GET settings`.
4. **Сбои.** Отклонённое сохранение называет проблему настройки в теле ответа. Найдите её в таблице Troubleshooting в `docs/006-deployment.md`, исправьте и продолжайте. Спрашивайте оператора только о том, что не можете исправить сами.

## 5. Проверка и передача

`scripts/dsh-superagent status` завершается с кодом 0 без проблем настройки. Если вы работаете в собственном профиле DSH оператора, создайте ежечасную проверку из раздела Hourly check в `docs/006-deployment.md` при помощи вашего инструмента расписаний; иначе передайте оператору её промпт для настройки там. Затем отправьте одно сообщение, в пределах 300 слов:

- URL панели и то, что пункт **Superagent** в боковой панели — то место, куда смотреть.
- Как попробовать: с аккаунта из списка разрешённых напишите комментарий `@<логин агента> <запрос>` к issue в репозитории. Тикет появится в обзоре примерно в течение минуты.
- Три правила для оператора из раздела Responsibility в `docs/000-philosophy.md`: начинайте узко, настраивайте на меньший шум, отвечайте за то, что говорит агент.
- Где читать дальше: нумерованные документы в `docs/`, по порядку.
